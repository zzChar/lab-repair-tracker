## Intent

**问题**　负责人能查看待接单工单，但还不能认领工单。

**方案**　负责人从待接单详情提交接单。服务端检查角色，并按工单编号、状态、跟进人是否为空和页面版本执行条件更新。接单成功后进入处理中，记录跟进人、更新时间、递增版本和接单事件，工单出现在该负责人的接下列表。普通成员、旧版本或竞争失败的请求不能改变工单。

</frozen-after-approval>

## Implementation Notes

- 新增需登录和 CSRF 的接单 POST 入口。提交版本来自详情页面，跟进人取当前负责人会话。普通成员在进入写事务前被拒绝，写事务中再次确认负责人组权限。
- 复用待接单且无跟进人的查询条件，按编号及预期版本更新。工单状态、跟进人、版本、更新时间和接单事件一起提交或回滚。版本或状态冲突返回 409，SQLite 写锁超时返回 503。
- 成功后进入「我接下的工单」。报修人刷新详情可看到跟进人。接单事件类型迁移 0003 已应用。
- 系统检查、迁移一致性检查及 34 项自动化测试通过。临时文件数据库上的多线程 Django WSGI 服务完成三轮双负责人并发接单，每轮一条请求成功、一条返回 409，且只追加一条接单事件。核对了负责人列表和报修人详情。
- Git 根位于练习目录上级，本次交付保存在练习目录。
