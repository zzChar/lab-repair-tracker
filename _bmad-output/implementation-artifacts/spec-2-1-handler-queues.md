## Intent

**问题**　负责人可以登录，当前入口尚未显示需要跟进的工单。

**方案**　负责人分别查看待接单与本人接下的工单，列表显示编号、设备、状态、跟进人和最近更新时间。详情允许报修人查看本人提交的工单，并允许负责人查看待接单和本人接下的工单。无关人员访问详情返回通用 404。

</frozen-after-approval>

## Implementation Notes

- 现有负责人入口显示待接单队列，增加独立的「我接下的工单」入口。两者与个人列表共用列和排序。待接单队列只选待接单且尚无跟进人的工单，接下列表按当前会话负责人匹配跟进人。
- 详情在统一查询中保留报修人权限，并按负责人组开放上述两个队列中的详情。对无关负责人保留通用 404。
- 增加「处理中」状态选项。迁移 0002 只调整模型选项，SQL 检查为无数据写入的空操作，已在练习库应用。已接单数据在验证库内预置，接单写操作由故事 2.2 交付。
- Django 系统检查和 29 项自动化测试通过。临时数据库上的实际 HTTP 请求验证两个负责人均能查看共同待接单队列和各自接下的工单，直访对方工单返回 404。普通成员进入负责人队列返回 403，原报修人仍可打开自己的已接单工单。
- Git 根位于练习目录上级，本次交付保存在练习目录。
