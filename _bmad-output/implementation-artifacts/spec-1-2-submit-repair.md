## Intent

**问题**　成员能登录应用，但还无法记录公共设备故障。

**方案**　登录后填写设备名称、位置和故障描述。有效提交以当前会话用户为报修人，生成一张待接单、无跟进人的工单。工单摘要和带操作者、时间及版本的创建事件一起提交。字段缺失时指出对应字段，工单和创建事件均不增加。成功后展示工单编号和状态。

</frozen-after-approval>

## Implementation Notes

- 新增 `repairs` 应用和首个迁移。在已有练习数据库应用迁移，保留 1.1 的演示账号。
- 登录后可从首页打开报修表单。服务端只接收三个业务字段，报修人来自会话。工单以待接单、无跟进人、版本 1 创建。创建事件与工单共用服务端时间并在同一事务提交。
- 成功后重定向首页并显示工单编号与状态。缺少字段或字段全为空白时原地标记对应字段。非空白内容保留原值。数据库锁等待超时返回 503 并保留填写内容。
- 通过 Django 系统检查、迁移一致性检查和 15 项自动化测试。实际 HTTP 演练用隔离的文件数据库验证了登录后提交、三个必填字段、真实锁超时、释放写锁后重试、精确的工单和事件字段，以及刷新首页不重写。
- 本地 Git 根位于练习目录上级，项目没有独立的提交基线。改动保存在练习目录。
