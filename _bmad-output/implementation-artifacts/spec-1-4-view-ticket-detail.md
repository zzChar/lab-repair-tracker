## Intent

**问题**　报修人能找到工单列表，但还不能打开一条记录核对故障信息。

**方案**　从个人列表的工单编号进入详情，显示编号、设备名称、位置、故障描述、状态和最近更新时间。详情在当前会话用户可见的工单范围内查找。无权访问与编号不存在统一返回通用 404。用两个普通成员验证授权访问与直接越权访问。

</frozen-after-approval>

## Implementation Notes

- 工单列表的编号链接到只读详情。详情沿用个人列表的报修人过滤，按当前会话身份和工单编号查询，不从请求参数接受身份。
- 报修人可核对工单编号、设备名称、位置、故障描述、状态和按本地时区显示的最近更新时间。未经授权与编号不存在使用相同的通用 404，拒绝页面不接收工单对象。详情和拒绝响应均禁止存储缓存。
- Django 系统检查、迁移一致性检查和 24 项自动化测试通过。临时 SQLite 文件上的实际 Django HTTP 流程使用两个普通成员分别登录并提交工单。双方查看自己的六个字段成功，直访对方工单均返回与不存在编号相同的 404 响应正文。匿名直访跳转登录。
- Git 根位于练习目录上级。本次实现保存在练习目录。
