- (constraint) 继承 PRD 中单实验室范围、四种状态、原单原负责人退回、两条端到端验收路径。NFR-1 和 NFR-2 按 PRD 草稿目标设计。
- (assumption) AD-1 建议采用 Django 服务端渲染的分层单体。前后端分离会增加 API 契约及演示启动成本。
- (assumption) AD-2 暂拟 SQLite 本机文件，写操作使用短 IMMEDIATE 事务。评审按单机部署估算。独立数据库服务增加启动成本，写争用如超出预期则复核。
- (assumption) AD-3 统一工单写入口，条件更新校验状态、操作者和版本。只校验状态无法识别上一轮验收页面的迟到请求。
- (assumption) AD-4 使用 Django 会话身份和负责人组，服务端集中约束工单可见性与操作资格。客户端角色或按钮隐藏不能限制直接请求。
- (assumption) AD-5 工单摘要和追加式事件在同一事务提交。覆盖式备注丢失上次验收与退回历史，分开提交可能出现状态与记录不一致。
- (question) 交付环境、测试帐号与负责人组的配置方式、依赖精确版本待锁定。待用两个独立数据库连接验证并发冲突和跨轮迟到请求。
