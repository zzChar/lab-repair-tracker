# 实验室报修跟踪 · 需求文档

本稿基于[组员已确认的产品简报](../../briefs/brief-BMAD-Codex-练习-20261108-2026-11-09/brief.md)，供小组评审第一版需求及验收标准。

## 1. 目标与使用者

为单个实验室的公共设备提供报修台账。成员在群里报过故障后，最容易遇到的是有人接单却没有后续消息。第一版让报修人能查到谁在跟进、最近做了什么、什么时候更新，并在实际验证设备可用后关闭工单。

- **工单**是一次报修从提交到关闭的记录，包含设备、故障、状态和处理过程。
- **报修人**是提交该工单的实验室成员，负责验证修复结果。
- **负责人**是能接单并处理报修的人员。当前跟进人是已接下这条工单的负责人。

## 2. 范围

**第一版范围**包括提交、查询、接单、更新进度、提交验收、确认关闭和验收失败退回。验收退回与复测沿用原工单。

**范围外**包括跨实验室管理、自动催更、图片附件、负责人转派、独立设备台账和统计报表。

## 3. 功能需求

### 3.1 报修与查询

| 编号 | 需求与可验收结果 |
| --- | --- |
| FR-1 | 成员提交设备名称、位置和故障描述后，系统创建工单，记录报修人，初始状态为「待接单」。 |
| FR-2 | 报修人能在列表查到自己提交的工单。列表项显示设备、状态、跟进人和最近更新时间，未接单时显示尚无跟进人。 |
| FR-3 | 负责人能分别查看待接单工单和自己接下的工单。列表项显示与 FR-2 相同的信息。 |
| FR-4 | 报修人可查看自己提交的工单详情，负责人可查看待接单工单和自己接下的工单详情。详情显示设备和故障、状态、跟进人、工单最近更新时间、进度历史、处理结果和退回原因。有进度记录时，显示最新一条进度及其记录时间。 |

工单最近更新时间是最近一次成功提交或修改工单的时间。最新进度时间取自 FR-6 的进度记录。

### 3.2 接单与处理

| 编号 | 需求与可验收结果 |
| --- | --- |
| FR-5 | 负责人接下「待接单」工单后，系统记录其为当前跟进人，并将工单转为「处理中」。 |
| FR-6 | 当前跟进人可以多次更新「处理中」工单。每次更新追加一条含内容和时间的进度记录，工单继续处于「处理中」，历史记录可查。 |
| FR-7 | 当前跟进人为「处理中」工单填写处理结果并提交验收后，系统保存处理结果，将工单转为「待确认」，供报修人验证。 |

### 3.3 验收与关闭

| 编号 | 需求与可验收结果 |
| --- | --- |
| FR-8 | 只有该工单的报修人可以在「待确认」时确认修好。确认后，原工单进入「已关闭」。 |
| FR-9 | 只有该工单的报修人可以在「待确认」时退回工单，且失败原因必填。退回后，原工单进入「处理中」，由原负责人继续跟进。原负责人能查看退回原因，之前的进度和处理结果可查。原因缺失时拒绝退回，工单仍处于「待确认」。原负责人可按 FR-6、FR-7 继续更新进度并再次提交验收。 |

## 4. 状态与操作

| 当前状态 | 可执行操作 | 后续状态 |
| --- | --- | --- |
| 提交前 | 成员提交（FR-1） | 待接单 |
| 待接单 | 负责人接单（FR-5） | 处理中 |
| 处理中 | 当前跟进人更新进度（FR-6） | 处理中 |
| 处理中 | 当前跟进人提交验收（FR-7） | 待确认 |
| 待确认 | 报修人确认修好（FR-8） | 已关闭 |
| 待确认 | 报修人填写原因并退回（FR-9） | 处理中 |
| 已关闭 | 查看记录（FR-2 至 FR-4） | 已关闭 |

## 5. 非功能需求

以下两条为草稿提出的可测约束，供小组评审。

| 编号 | 质量要求 | 验证方法与通过条件 |
| --- | --- | --- |
| NFR-1 | **并发一致性。** 同一轮验收只允许产生一个结果。关闭和退回发生冲突时，工单状态与成功操作的记录必须一致。 | 准备一条「待确认」工单，用同一报修人的两个会话并发提交确认关闭和带有效原因的退回。恰好一个请求成功，另一个收到状态已变化的提示。重新查询同一工单，只有一个成功结果。若关闭成功，工单为「已关闭」，无本轮退回记录。若退回成功，工单为「处理中」，保留原跟进人并记录本轮退回原因。 |
| NFR-2 | **权限隔离。** 每次读取和变更都要按当前身份、工单归属与状态校验权限。 | 检查无关成员的列表中查不到该工单，直接请求详情也被拒绝。另一位负责人尝试更新该工单，以及当前跟进人尝试确认关闭，均被拒绝。两次越权写入尝试前后，工单状态和处理记录一致。对应的有权限请求在满足状态条件时可以成功。 |

## 6. 主案例与端到端验收

**公共打印机卡纸。** 成员提交报修后看到「待接单」。负责人接单，工单转为「处理中」，并记录「已取出卡纸，正在检查进纸口」。报修人打开详情，能看到**跟进人、最新进度及其更新时间**。负责人填写处理结果并提交验收，工单进入「待确认」。两条路径均检查这些共同步骤（FR-1 至 FR-7）。

1. **验收路径 A · 试打成功关闭。** 报修人试打一页，确认出纸正常后关闭。验收通过条件是原工单显示「已关闭」，此前进度和处理结果仍可查（FR-4、FR-8）。
2. **验收路径 B · 试打失败退回。** 报修人试打一页仍卡纸，填写失败原因并退回。验收通过条件是工单编号和跟进人与退回前一致，状态回到「处理中」，失败原因和先前记录可查。原负责人继续处理并再次提交验收，报修人复测通过后关闭同一工单（FR-4、FR-6 至 FR-9）。

第一版验收以两条端到端路径和两项 NFR 检查全部通过为准。
