# 实验室报修跟踪 · 项目上下文

第一版是面向单个实验室的公共设备报修台账。按现有故事顺序交付报修与查询、接单与跟进、验收与关闭。实现前从故事卡定位 FR、NFR 和 ADR，再按该故事的 AC 编写测试。 [PRD](prds/prd-BMAD-Codex-练习-20261108-2026-11-09/prd.md) · [架构约束](architecture/architecture-BMAD-Codex-练习-20261108-2026-11-09/ARCHITECTURE-SPINE.md) · [ADR](architecture/architecture-BMAD-Codex-练习-20261108-2026-11-09/architecture.md) · [史诗与故事](epics.md)

## 技术栈和版本

| 项目 | 第一版基线 | 当前证据与落实位置 |
| --- | --- | --- |
| 语言 | Python 3.12 系列 | 交付机实测 3.12.10，`pyproject.toml` 限定 Python 3.12 系列。 |
| Web 框架 | Django 5.2 LTS | `pyproject.toml` 与 `uv.lock` 固定为 5.2.19，交付机实测一致。 |
| 页面与身份 | Django 5.2 模板、表单、会话和用户组 | 服务端渲染的分层单体。成员与负责人使用独立演示账号，服务端用负责人组判断角色。 |
| 持久化 | Python 自带 `sqlite3`，单机文件数据库 | 交付机实测 SQLite 3.49.1，写事务采用 `IMMEDIATE`。 |

故事 1.1 已建立应用骨架和依赖锁定，账号初始化、启动及测试命令见[仓库 README](../../README.md)。

## 实现规则

1. **工单由服务层统一写入。** 页面入口解析表单、调用服务、展示结果。新建、接单、追加进度、提交验收、关闭和退回都进入同一个工单写入服务。查询通过统一查询服务。对应 ADR-001。
2. **身份从服务端会话取得。** 从登录账号和负责人组推导操作者及角色。列表与详情共用可见性规则。普通成员只能看自己报的单，负责人还可看待接单和自己接下的单。对应 FR-2 至 FR-4、NFR-2、ADR-004。
3. **写入同时检查资格和状态。** 待接单由负责人接下。处理中由当前跟进人更新或提交验收。待确认由该单报修人关闭或退回。每次写入执行服务端校验，详情入口同样校验对象权限。对应 FR-5 至 FR-9、NFR-2。
4. **所有既有工单的写入携带读取时的版本。** 在事务中按工单编号、预期状态和预期版本做条件更新。更新成功后版本加一，进度更新也加一。零行更新按冲突处理，提示刷新。旧页面的请求即使遇到下一轮同样的「待确认」状态也会被拒绝。对应 NFR-1、ADR-003。
5. **工单摘要与事件在同一事务提交。** 每次成功写入追加一条事件，记录工单版本、操作者、动作和服务端时间。状态、版本、时间与事件一起提交或一起回滚，提交后才返回成功。对应 ADR-005。
6. **SQLite 写事务保持短小。** 使用文件数据库和显式 `IMMEDIATE` 写事务，页面渲染在事务外完成。锁等待超时返回暂时不可用，状态或版本不匹配返回冲突。对应 ADR-002、AC-3.4c。
7. **进度时间和工单更新时间分别读取。** 工单更新时间跟随最近一次成功写入。最新进度时间取自最近一条进度事件，历史按工单版本排序。提交验收或退回仍能看到此前进度。对应 FR-4、FR-6、ADR-005。
8. **验收失败退回原单。** 失败原因去掉首尾空白后必须有内容。成功退回时工单编号和跟进人不变，新增退回事件，状态回到「处理中」。再次提交验收时保留前一轮结果。对应 FR-9、AC-3.2a 至 AC-3.2c。
9. **按故事增量建立数据结构。** 1.1 只准备 Django 认证、会话和演示账号所需的结构。1.2 引入工单和事件。后续状态、页面及迁移随用到它们的故事交付。对应 ADR-001 和故事 1.1、1.2。
10. **并发测试用文件数据库与独立连接。** 同一报修人的两个会话分别提交同版本的关闭和退回，分别验证两种胜出结果。另测旧版本、事件追加失败回滚和锁等待超时。用数据库最终状态和事件数作断言。对应 NFR-1、AC-3.3a 至 AC-3.4c。
11. **权限测试直接请求服务端。** 覆盖无关成员查询列表和直访详情、其他负责人更新、跟进人代为关闭。越权写入前后比对状态、版本和历史。对应 NFR-2、AC-1.3a、AC-1.4b、AC-2.3c、AC-3.1b。
12. **验收证据按编号归档。** 为两条 NFR 保留对应测试结果。端到端分别用两张打印机卡纸工单验证成功关闭与失败退回后复测关闭，检查跟进人、最新进度和记录时间。对应 PRD 的两条验收路径。
